Dispatch board

Replit runs parallel agents behind a paid toggle. Here, planning and parallelism are the harness's own disciplines: dated dispatch files, waves that run in order, and lanes that each own a disjoint set of files. The board renders the batch files in os/dispatch/batches/, read straight from the snapshot. It ships with two worked examples; an instance's own batches appear beside them.

How a dispatch prompt is built

Each prompt is a self-contained work order. Six sections are required, in order:

  1. MISSION · one directive: what the lane must produce.
  2. CONTEXT LOAD · the ordered files to read first, and what to take from each.
  3. OUTPUT SPEC · the exact files, paths, and formats to write.
  4. CRITICAL CONSTRAINTS · the non-negotiable rules: voice, hermetic seal, classification.
  5. SMOKE TESTS · binary checks the lane runs before it claims done.
  6. QUALITY GATE · what "done" means, written as a checklist.

Waves and OWNS. A batch runs in numbered waves. Within a wave, lanes run at the same time because each lane OWNS a disjoint set of files and never writes another's. Shared foundations freeze once they are built, and a single convergence lane folds the parallel work together and carries the status flips.

Row statuses reflect each file's frontmatter at snapshot time and lag per-lane merges until the convergence pass regenerates the snapshot.
