name: heyhi-design-bridge
description: >-
  Bridges HeyHi's generative and code outputs into editable, brand-grade design
  artifacts, as one agentic skill with two modes. Translate turns a ui-studio HTML
  prototype into responsive Figma mockups plus a documentation frame (color fills
  bound to Figma Variables) via a reviewed scene-graph IR and the official use_figma
  MCP. Vectorize turns a Nano Banana raster into a craft-quality SVG (few anchor
  points, clean curves) via quantize, trace, simplify, and a human polish step. Use
  when the user says "translate this prototype to Figma", "HTML to Figma", "Figma
  documentation from the prototype", "vectorize this", "vectorize this mark", "raster
  to vector", or "nano banana to SVG". No custom Figma plugin. NOT for building
  prototypes (use heyhi-ui-ux / ui-studio), auditing a design system (use
  heyhi-design-intelligence-audit), prototype-readiness (use heyhi-prototype-audit),
  designing a logo (use heyhi-logo-system), extracting Figma tokens into a config
  (use ui-studio-onboard, the opposite direction), vector-to-STL fabrication (use
  heyhi-fabrication-prep — planned, not built; see CANDIDATES.md), or creating
  infographics/essay visuals from source content
  (a build task: author SVG directly or use heyhi-ui-ux; design-bridge only lands or
  vectorizes finished art).

# HeyHi Design Bridge

One agentic skill, two modes, one shared idea: take a generative or code output and land it as an editable, brand-grade design artifact, with the human kept at the points where judgment belongs.

- **Translate** turns a `ui-studio` HTML prototype into Figma documentation and mockups.
- **Vectorize** turns a Nano Banana raster into a craft-quality SVG.

The spine that ties them together is a **Scene-Graph IR**: a JSON contract between reading the source and writing the artifact. The IR is validated and diffed without opening Figma, and it is the artifact the human reviewer approves before any canvas write. The official `use_figma` MCP (hosted Plugin-API execution) is the write path; there is no custom Figma plugin.

For the IR field reference, the CSS-to-Figma mapping table, the vector parameters, the re-run contract, the golden sets, and the verification criteria, see [reference.md](reference.md). The full rationale lives in the approved build plan (a local plan file, not shipped).

## Mode 1 — Translate (HTML to Figma)

Input: a `ui-studio` / `heyhi-ui-ux` HTML prototype (semantic HTML, values driven by CSS custom properties named from `brand-config`). Output: one frame set per breakpoint side by side on a shared page plus a merged documentation frame. Runs end to end from one chat invocation; the only stops are the IR approval and the human craft pass. Paths below are relative to the skill folder; the Figma write needs a live session (the user opens a scratch file, or names a real one, and the agent drives `use_figma`).

**1. Invoke + confirm inputs (one line).** Confirm the prototype path, the breakpoints (`sm` 375 / `md` 768 / `lg` 1440), and the brand config, then proceed. Example: "Translate the atlas-reader prototype at sm/md/lg, example config, set-direct."

**2. Extract + validate** (headless Chromium via Playwright; Phase T1). One IR per breakpoint, recovering tokens from the **declared** stylesheet values (not `getComputedStyle`, which returns literals) and routing every does-not-map feature into `IR.flags` — nothing dropped silently.

```bash
# install once: npm install --prefix scripts/extract_scene_graph && \
#   scripts/extract_scene_graph/node_modules/.bin/playwright install chromium
node scripts/extract_scene_graph/extract.mjs --prototype examples/prototypes/atlas-reader.html --name atlas-reader
python3 schema/validate_ir.py examples/atlas-reader.{sm,md,lg}.ir.json   # must PASS for all three
```

> **Font preflight (before building, v0.14.0).** A silent typeface substitution is invisible until the render, so resolve every requested face — inline runs included — against the target workspace's real catalogue first. Dump the catalogue once in Figma (`figma.listAvailableFontsAsync().then(f => console.log(JSON.stringify(f)))`), save it, then: `python3 scripts/preflight_fonts.py --available <catalogue.json> examples/atlas-reader.{sm,md,lg}.ir.json`. It maps each `(family, weight)` the build will request with the builder's own weight→style table and exits non-zero on any unresolvable pair (e.g. `Sora Medium`, or a `DM Mono` run inheriting weight 600 → `DM Mono SemiBold`, which does not exist — a per-node scan misses the inline run). Fix the source or map the weight before the write.

**3. Approval surface (Earn the Room).** Before any canvas write, render the IR as a scannable summary — frame tree, per-breakpoint node counts, tokens bound vs. their provenance (declared / matched, low-confidence flagged), the type ramp, the chunk plan, and the highlighted flags block — and get the human reviewer's approve / edit / reject. This is read-only; it writes nothing.

```bash
python3 scripts/build_figma.py examples/atlas-reader.{sm,md,lg}.ir.json --summary
```

> **Scope from the summary before issuing chunks.** Read the `--summary` node/chunk counts and the flags ledger and make a scope call **before** step 4 issues chunks. When the flag density is image-heavy and the plan is many chunks per breakpoint, build `lg`/desktop first and surface the cost/value tradeoff before committing to all breakpoints. (Since v0.7.0/v0.8.0 image handling is real, not placeholder: an SVG lands as an editable VECTOR via `createNodeFromSvg` with per-unique-mark dedup, and rasters embed full-res via the Figma MCP `upload_assets` tool — placeholder flags now mark only unresolved assets, so flag density signals cost, not lost fidelity.) The validated `sm`/`md` IRs stay staged for a one-command continuation.

**4. Build the plan + run the chunks.** `build_figma.py` turns the reviewed IRs into an ordered set of `use_figma` chunks (a compact op-array plus a fixed interpreter), chunked by **projected character length** so each payload clears the 50,000-char per-call cap — `--summary` forecasts the max projected payload, and the build hard-errors rather than emit an over-cap chunk. (The earlier count-based chunker blew the cap on a logo-heavy page; the char-budget chunker is regression-guarded by the logo-heavy golden, `examples/logo-wall.lg.ir.json`.) **SVG dedup:** each unique SVG is imported once as a Figma component and reused by instance, so a mark used many times carries its bytes once — this is what collapses an SVG-heavy page from dozens of chunks to a handful. **Componentization (WS5, v0.13.0):** the same dedup idea applied to repeated *structure* — a run of 3 or more consecutive siblings sharing one structural signature (a content card, an interactive control, or a chip/pill — headed by a heading-ish, control, or pill role-gate) collapses to one Figma component master carrying TEXT properties for its varying kicker/title/body/label, plus N lightweight instances setting each member's values. **Icon swapping (C2, v0.16.0):** where a card's icon differs across the run (a different SVG per card), that icon slot becomes an `INSTANCE_SWAP` property — each distinct icon dedupes to one SVG component master and every instance swaps to its own, so the icon is editable and shared, not re-inlined per card; an icon identical across the whole run stays baked into the master (one copy). A sibling that breaks the run's signature (a varied card) stays an independent frame, never dropped; `--summary` reports each detected group, its properties, and any excluded varied sibling under "Componentization." A chunk pays the (small) interpreter cost for the master/instance handlers only when it actually carries one, so a component-free page chunks exactly as before. `run_build.py` is the runner: it fills the `__IDMAP__` placeholder from the ids earlier chunks return (pruned to each chunk's `needs`), threads them forward so later chunks parent into earlier ones (including a master created in an earlier chunk than its instances), and accumulates the landing report. Color fills bind to Variables; type follows `--type-mode` (below); fonts resolve at runtime (numeric weight to a Figma style name; a missing font is flagged and falls back to Inter, never silently) — preflight with `listAvailableFontsAsync()` filtered to the brand families to confirm they exist and capture the exact style-name spelling before the write (reference.md §2); vectors import via `createNodeFromSvg`. **Rasters embed via the Figma MCP `upload_assets` tool** (raw bytes → cover fill on the node, full-res, no base64): after the chunks land, `run_build.py assets` lists each raster's node id + local path; the inline `figma.createImage(base64)` step is retired for rasters. A single SVG master too large even alone is flagged — run with `--svgo` (reference.md §F3) to shrink each unique mark.

```bash
python3 scripts/build_figma.py examples/atlas-reader.{sm,md,lg}.ir.json \
    --out-dir /tmp/atlas-build --rerun replace          # [--type-mode bind|style] [--max-nodes N]
python3 scripts/run_build.py self-test examples/atlas-reader.{sm,md,lg}.ir.json   # prove threading + the WS2 geometry gate (no Figma)
python3 scripts/run_build.py self-test examples/wrapping-grid.lg.ir.json          # the v0.4 wrap golden: geometry PASS, layoutWrap forwarded
python3 scripts/run_build.py init /tmp/atlas-build
# then, per chunk, until the report says complete:
#   python3 scripts/run_build.py prep   /tmp/atlas-build      -> writes chunk_<i>.ready.js
#   read chunk_<i>.ready.js, issue its contents via use_figma(fileKey, <contents>)
#   python3 scripts/run_build.py record /tmp/atlas-build --result '<the use_figma return JSON>'
python3 scripts/run_build.py assets /tmp/atlas-build    # raster embeds: node id + path -> upload_assets(nodeId), then POST bytes
python3 scripts/run_build.py report /tmp/atlas-build
```

> **The build can BLOCK (v0.14.0) — a green build is a shippable one.** Two cases refuse to emit rather than ship a wrong approximation: a css-grid whose `grid-column` spans cannot be partitioned, and a visible `::before`/`::after` the builder cannot place (below). `build_figma.py` exits non-zero and stamps `manifest.blocked`; `--allow-blocking` downgrades the exit for measurement/inspection only (the plan is still marked blocked); `run_build.py init` refuses to issue a `manifest.blocked` build to Figma. `self-test` forwards `--allow-blocking` — it validates plumbing, not shippability.

> **Visible `::before`/`::after` (R-1=D region-scoped block, v0.14.0).** A pseudo-element carrying a visible box on a **leaf frame host** — the common coverage-bar / progress-fill pattern (`position:absolute; inset:0; width:var(--fill)`) — is emitted as a `needs-human` **placeholder** at its captured box (`getComputedStyle` resolves the geometry to px in Chromium for a positioned host), so the build ships with the region marked and a human confirms the real paint. A pseudo the builder **cannot** place faithfully — a non-leaf/non-frame host, or a box that does not resolve (a `position:static` host, a `fixed` pseudo) — BLOCKS instead: refuse rather than silently drop.

One frame set per breakpoint lands side by side, plus a self-describing documentation frame (token + Variable map, type specimen, flags ledger). `--rerun replace` clears and rebuilds the dedicated build page; `--rerun version` writes `<page> vN`; the token collection and Variables find-or-create, so a re-run reuses them rather than duplicating. When that reused collection is a **canonical** one (e.g. a Color foundations page authored separately), `doVariable` sets values on **create only** (v0.6.0), so the build does not overwrite canonical values; a deliberate value change to an existing Variable is then an explicit action (reference.md §5, Canonical-collection reuse hazard).

**5. Report.** `run_build.py report` states what landed: the page, mockup vs. documentation nodes, color Variables created vs. reused, the IR flags carried into the doc frame, and any build-time font/asset substitutions and errors.

**6. Review** (human, in Figma). Craft check, resolve flagged items, accept. Design critique stays human.

> **Earn the Room.** The IR summary (step 3) is the approval surface, and the human opens Figma and initiates the write. The write is a faithful render of the approved IR, not a free-form generation.

> **Type mode (`--type-mode`).** Color always binds to Figma Variables. Typography is a choice, and the documentation frame records which mode ran so the reviewer sees it:
> - **`set-direct`** (default): type values (family, style, size, line-height, letter-spacing) are written directly onto each text layer, with the source token recorded as `token_ref`. The file carries no typography Variables. Best when the client library does not model type as Variables.
> - **`bind`**: the same values bind to Figma Variables, so editing a type token in Figma updates every layer. This needs the client's Figma to model typography as string and float Variables, and it couples the write to font availability. Caveat: a Variable-bound `lineHeight` coerces to pixels in Figma (proven live 2026-06-17), so the `bind` path's `lineHeight`/`letterSpacing` binds are subtly wrong; prefer `style` when you want shared named styles.
> - **`style`** (WS3, v0.4): writes type **set-direct on first paint** (correct first render, no type bindings), then surfaces a post-build finish in `--summary` — `compose_type.py extract -> review/rename roles -> emit -> issue create.js + apply.js via use_figma` — which lands one shared, named **Figma Text Style** per role (`createTextStyle` + `setTextStyleIdAsync`), binding family/style/size to Variables but setting lineHeight/letterSpacing direct (avoiding the pixel-coercion above). Role names are token_ref-aware (`body-lg -> Body/Large`, heuristic only as fallback). The recommended path when the client wants real Figma Text Styles; no in-interpreter port (it would couple the write to font-load ordering for no functional gain). **The same `compose_type.py` finish also works surgically (Compose, v0.13.0):** retrofitting a type system onto a page that already has a structural build — from a prior Translate run, or built any other way — rather than as a fresh-build post-step. `apply.js` classifies each *existing* TEXT node by its current resolved font/size/spacing instead of reading a fresh IR. Live-proven 2026-06-17; see reference.md §5b, "Surgical finish."
>
> The T2 spike confirmed typography *can* bind (reversing the plan's earlier premise). The default stays `set-direct` by choice; `bind` is there when the client's system wants in-Figma type traceability via Variables; `style` is the path to shared named Text Styles, flip the default to it after one live pass proves the finish end-to-end.

## Mode 2 — Vectorize (Nano Banana raster to craft SVG)

The trace-and-simplify core is fully headless; the optional Figma landing reuses the live-session write path. Scripts: `scripts/vectorize/` — Phase V, built and ratified. One command runs steps 2-5 and prints the craft report:

```bash
# deps once: pip install --user vtracer Pillow numpy; brew install potrace librsvg; npx svgo (auto)
python3 scripts/vectorize/vectorize.py INPUT.png --class mark|illustration \
    --out OUT.svg --fidelity --json OUT.report.json
# brand colors: --palette "#RRGGBB,#RRGGBB,..."  (defaults to the instance palette, if its calibration sets one)
```

**0. Locate + segment the input.** Two input realities the single-raster goldens miss. **(a) Pasted input:** if the source was pasted into chat rather than given as a path, locate the file on disk first — match by pixel dimensions and mtime, confirm visually — the trace pipeline needs a file. **(b) Multi-subject sheets:** generative output is often a grid (icon / logo-variation / specimen sheet), not one raster. Segment before tracing: build a dark-on-light ink mask, max-pool downsample, lightly dilate to bridge intra-subject stipple gaps *without* merging neighbours, flood-fill label the components (no scipy needed), render a **numbered overlay**, and map numbers → named subjects against the request; crop each requested subject with a small pad and trace it independently. Tune the dilation to bridge stipple gaps but stay smaller than the inter-subject gap — if subjects merge or fragment, re-detect rather than hand-crop blind. **Probe the hardest subject first:** before committing a treatment across the set, run the most texture-heavy subject through the candidate treatments, read the real anchor counts and a rendered preview, and choose from evidence — the hardest subject sets the anchor floor for the batch. **(c) Pasted source not on disk:** recover it from the session transcript jsonl (`~/.claude/projects/<encoded-cwd>/<session>.jsonl`) — walk the content blocks for a base64 image payload, decode, save. A pasted image is often **WebP** (base64 begins `UklGR`/RIFF), which a PNG/JPEG-only grep misses; match `image/webp` too. Confirm by pixel dimensions before tracing.

**1. Generate, vector-friendly** (upstream — and load-bearing, not optional, for anything headed to a clean vector). Prompt Nano Banana / Gemini Image for flat color, limited palette, hard edges, no gradients or noise — and specifically **no woodcut/engraving texture or hatching**. The real-art re-validation showed that textured/woodcut output cannot trace to a clean few-point vector (texture caps the fidelity proxy well below the bar and runs into the thousands of anchors); flat generation is what lets a detailed subject land in the gated flat tier instead of the human-judged detailed bucket. Build on `marketing/essay-visuals/nano-banana-2-prompt-pack.md`. Generating brand marks is opt-in per the 2026-05-29 logo-system rule; render only on request. The trace path does not generate.

**2. Quantize** (Pillow), dithering off, despeckle. For an illustration the quantize is **palette-locked** to the brand color tokens (`--palette`, default: the instance palette) and the traced fills are **snapped back** to those tokens — plain mediancut averages brand accents (red, blue) into a muddy merge that fidelity scores do not catch. A mark goes mono (Otsu threshold).

**3. Trace, tuned for few points.** `potrace` (mono mark) or `vtracer` (color illustration; spline + stacked). The primary lever for low anchor count is the trace parameters (calibrated per class in `presets.py`); see reference.md §4. For a **dense or detailed two-tone subject**, a direct 2-color trace can invert figure/ground (the dense region becomes a full-canvas base layer) — use the **render-then-potrace knockout** path in reference.md §4 instead.

**4. Cleanup plus optional curve-fit.** SVGO (conservative: precision only, viewBox + per-color layers kept). Then a Schneider curve-fit (`fit_curve.py`, never raw RDP) — **on by default for illustration** (it halved the golden's over-segmented curves with no fidelity loss), **off for marks** (refit rounds the corners that make a mark intentional).

**5. Human craft polish (the primary craft surface).** Reposition anchors, restore intentional corners the tracer rounds off, re-introduce any color the mono pass dropped, test at icon and hero scale. This is the don't-automate-this step and the bulk of the craft. The craft report ends with an explicit "your turn"; the tool never pretends the craft is finished. **Direction forks are human.** When the trace yields more than one valid look (e.g. bold-solid vs. engraved for a textured subject) rather than a clear winner, render both directions across the *whole set*, show anchor counts, and get a direction pick before finalizing the batch — make the fork concrete and cheap to decide, do not decide it. **Geometric-primitive refinement + keyline (§4a).** If a ring/badge traced wobbly and fused into the subject, refine it to true geometry (`refine_primitive.py`) and knock a managed keyline between frame and figure (`composite_keyline.py`), default `keyline_width` ≈ 1.8% of frame diameter. Verify with `assert_keyline_opens`, not a thumbnail (DEF-5).

**6. Land.** Place the SVG into a Figma frame (`use_figma` `createNodeFromSvg`, live session — Earn the Room) or store it in the existing `logo.marks[].asset` namespace with `$description` and provenance (the namespace shape is `heyhi-logo-system`'s; an instance's own landed-mark record, a `*.logo.json` beside its traced mark, is instance data and stays out of a scaffold export). For an object-in-frame mark, land the keyline as a live Figma **Boolean Subtract** (`ring − expanded_figure_svg()`, generated by `composite_keyline.figma_boolean_landing_js()`), not a flattened vector, so the keyline stays editable. Landing into a *real* client file (not a scratch file): `get_metadata` (page list → page), map top-level child bounding boxes, drop a labelled container frame in empty canvas, return its node id + position, and screenshot to verify holes imported transparent. Probe an oversized `get_metadata` result with `jq`, never line-by-line.

> **Calibration gate (Phase V.0): per instance.** Anchor ceilings are **pre-polish** and per **(class, tier)**: a traced asset comes in under its tier ceiling before the human polish step, and a **visual-fidelity bar** on `ssim·target` (re-rasterized trace vs the quantized flat target) applies at both hero and icon scale. The human makes the final accept/reject; polish time is reported, not gated. The **tier structure is the method**; the **numbers belong to the instance**, proposed by `calibrate.py` against the instance's own art and ratified by the instance owner. Select the tier with `--tier`:
> - **mark · flat** (geometric glyph/symbol) and **mark · organic** (animal/figure silhouette; an organic outline has a structurally higher anchor floor than a geometric one).
> - **illustration · flat** (vector-friendly limited palette).
> - **illustration · detailed** (woodcut/engraving): **no anchor ceiling, HUMAN-JUDGED.** Engraving texture caps the fidelity proxy and runs into the thousands of anchors, so no anchor gate is honest there. **Primary path: generate flat / vector-friendly (step 1) so it lands in the flat tier;** a traced woodcut is judged on recognizability with anchors + fidelity reported, not gated.
>
> Where the numbers live: `scripts/vectorize/presets.py` `CEILINGS` is the slot and ships **unratified** (`None` targets; Vectorize asserts no numeric target). An instance's ratified values live in `scripts/vectorize/instance_calibration.py`, which `presets.py` overlays when present. That file is **instance-only** and is not shipped in a scaffold export. An instance's values (ratified by its owner, and tiered after real-art re-validation) and their evidence trail are recorded there; the same file can set `GOLDENS` so `make_goldens.py` / `calibrate.py` calibrate against the instance's own mark and palette (generic default: a neutral example mark and palette).

**Data handling.** The real boundary is where an asset *goes*, not whether anything leaves the machine. Translate parsing (reading the prototype HTML and computing styles) is local. Raster embedding is not: when the Builder lands an `<img>` or a CSS `background-image`, the Figma MCP `upload_assets` tool POSTs the raster's raw bytes into the file (full-res, set as a cover fill on the node; this retires the inline `figma.createImage(base64)` path for rasters). Those bytes go only into the **client's own Figma file**, which is the deliverable target the client owns. That is categorically distinct from sending an asset to a **third-party generative service**: client-confidential assets are not sent to an external generative service without explicit client consent. Generation (Mode 2 concept imagery) sends prompts and any reference imagery to an external provider, so by default it is for HeyHi-originated concept imagery only; the trace pipeline is local. State the boundary as "client assets go only into the client's own Figma file," not "nothing leaves the machine."
